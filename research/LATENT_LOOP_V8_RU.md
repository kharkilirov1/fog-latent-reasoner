# FOG v8: латентный ризонинг внутри LLM без дискретного процессора

Дата: 2026-11-04. Связанные файлы: `research/notes/NOTE-016-attractor-capture-replaces-discrete-executor.md`,
`experiments/capture_theorem_check.py`, `experiments/capture_learned_operator_experiment.py` (EXP-040),
`experiments/fog_latent_loop_v8.py` (EXP-039).

## 1. Диагноз: почему дискретный процессор стал тупиком

Все последние эксперименты сходятся к одному результату:

| эксперимент | oracle-исполнение | end-to-end | узкое место |
|---|---:|---:|---|
| SmolLM dual-tap (Z_31) | 100% | 84% на R=12, 6.7% на парафразах | opcode-парсинг |
| Logic-v6 (Qwen 0.5B) | 100% | 46.8% | BIND-аргументы |
| Logic-v7 Copy-Bound | 100% | 50.2% | BIND = 72% |

Исполнитель всегда работает на 100%. Ошибка возникает в интерфейсе семантика → символ.
Этот интерфейс нужен только потому, что вычисление передаётся дискретной машине. Ошибка
парсинга `δ` на шаг даёт `(1−δ)^R`, и вернуть её нечем: дискретная машина не имеет
градиента обратно в смысл. Поэтому дальнейшая шлифовка парсера даёт мало.

## 2. Что сохраняется из FOG, а что убирается

Убираем: typed register machine, opcode/BIND-классификаторы, relation memory,
hard-ST operator routing, символический ALU.

Сохраняем как **свойства динамики LLM**, а не как отдельный модуль:

1. *Рекуррентная валидность* (§3 препринта): состояние шага t должно быть валидным входом шага t+1.
2. *Closure defect / gain* (§8): теперь это управляемые величины цикла.
3. *Gauge-неоднозначность* (§6): устраняется одним **общим** readout на всех шагах (NOTE-016, Prop. D).
4. *Дискретность* становится **аттрактором захвата** в непрерывном цикле (Theorem A′), а не процессором.

## 3. Главный теоретический результат (NOTE-016)

Цикл `h ← Π(F_c(h))`, где `F_c` — переход, который реализует сама LLM (инструкцию выбирает её
собственное мягкое внимание), а `Π_β` — Хопфилдов захват на кодовой книге.

* **Theorem A.** Тубус вокруг символической траектории инвариантен при `κ(Lr+ε)+η ≤ r`.
  Условие разрешимо тогда и только тогда, когда `κL < 1`. Без захвата нужно `L < 1`
  (это формула (15) препринта). Порог точный (Prop. B).
* **Theorem A′.** Если closure defect `ε < Δ/(2R)`, то для **любого** `L` существует конечная
  обратная температура `β*` (формула в NOTE-016), при которой цикл точен на всех глубинах.
  Дискретный процессор — это предел `β = ∞`; конечной температуры достаточно, и цикл
  остаётся дифференцируемым.
* **Prop. C.** Мягкий роутинг поглощается: `ε_eff ≤ ε + 2R'δ`. Hard-ST роутер больше не нужен.
* **Prop. E.** Нелинейный захват обходит линейное препятствие `d ≥ p−1` (Theorem 1):
  `β* ≍ (ln L + ln N)·N^{2/(d−1)}/R²`, т.е. ширину можно обменять на резкость аттрактора.

## 4. Проверки

При `β ≥ β*` точность 100% во всех случаях. Видно и Prop. E: при d=2 нужна β≈900,
при d=32 — β≈12.

### 4.3 EXP-039: латентный цикл внутри SmolLM2-135M (`fog_latent_loop_v8.py`)

Архитектура: замороженный промпт (KV-кэш, без градиента), затем латентные thought-токены
`[" Step t:"][x_t]` с thought-mode LoRA (r=8, 2.8M параметров). Это **собственные слои LLM**,
без отдельного исполнителя и без парсинга опкодов. Обратная связь:
`cont` (непрерывная, Coconut-подобная), `attr` (мягкий токен-захват), `hard` (ST-snap, эталон).
Thought 0 читает стартовое значение; общий readout на всех шагах.

Запуск: CPU, 4 ядра, 900 шагов, batch 16, курикулум глубины 1→4, 48 примеров на ячейку
(финальная точность, `id` = стили обучения, `held` = новый стиль формулировок):

| арм | R=1 id/held | R=2 id/held | R=3 id/held | R≥4 (среднее) |
|---|---:|---:|---:|---:|
| cont | 52% / 54% | 21% / 17% | 8% / 6% | ≈ 4% |
| attr (β=1) | 63% / 63% | 8% / 8% | 0% / 6% | ≈ 3% |
| hard (эталон) | 42% / 50% | 19% / 8% | 2% / 8% | ≈ 4% |

(шанс = 3.2%)

**Вердикт: UNDERPOWERED (недостаточно вычислений). Это не свидетельство ни за, ни против
захвата.** За 900 CPU-шагов LLM-цикл выучил чтение старта (thought 0 = 100%) и лишь
≈50–60% одношаговых операций. Значит, closure defect `ε` намного больше порога
`Δ/(2R)`, и предусловие Theorem A′ не выполнено. В этом режиме теорема не обещает пользы,
и захват действительно «защёлкивает» ошибочный код: tube-distance у `attr` растёт до
≈0.98, это расстояние до *другого* кода. У `cont` tube ≈ 1.41 не информативен, потому
что кодовая книга в этом арме не обучается. Корректная проверка требует сначала
довести одношаговое замыкание до `ε < Δ/2R` (≈100% на R=1). Это вопрос вычислительного
бюджета (GPU, ≥10k шагов), а не архитектуры.

## 5. Итог и следующий шаг

1. **Теорема (NOTE-016, A′).** Дискретный процессор можно заменить аттрактором захвата
   внутри непрерывного цикла LLM. Устойчивость на всех глубинах требует только
   `ε < Δ/2R` и `β ≥ β*(ε, L)`. Условие `L < 1` больше не нужно.
2. **Эмпирика.** Выученный гибкий оператор с L≈4 (как в провале на рис. 1) непрерывным
   захватом стабилизируется до 100% на глубине 256 в 6/6 запусках.
3. **Следующий шаг (GPU):** EXP-039 на Qwen2.5-0.5B, ≥10k шагов, β-аннилинг до `β*`,
   coprime-глубины, held-out парафразы. Главная метрика — экстраполяция R=5..12 у `attr`
   по сравнению с `cont`, плюс tube-distance `‖x_t − c_{v_t}‖` (теорема предсказывает, что
   у `attr` она ограничена, а у `cont` растёт). Затем — задача Logic-v7 без BIND-парсера:
   сущности становятся кодами захвата, отношения LLM исполняет сама.
